Failure modes

6 real bugs surfaced through actual testing — every one disclosed, not just the flattering ones.
✓ Fixed

Aether Chat was fully non-functional — missing schema, missing method. Every call failed before reaching an LLM.

✓ Fixed

Hours input took the first number found, no unit-check. Rebuilt as tappable per-day options.

✓ Fixed

"Life Happened" silently failed without a same-day Day Output. Now auto-submits a full-miss day.

✓ Fixed

Search tool was optional per instructions — links often missing. Now mandatory for Smart Spend.

◐ Open decision

After 1 LifeLoad approval, Reserve marks fully used all week — even tiny disruptions need re-approval.

🔧
3 smaller fixes
A casing bug breaking every disruption report, a session-restore edge case, an overly open CORS setting.
7

Guardrails

✓Numbers never AI-generated — only framing is.
✓Reserve buffer never named or quantified to the user.
✓No medical, financial, or legal specifics.
✓No suggestion reduces child supervision.
✓Every number carries a one-line justification.
✓Links only from real search results.

V1 → V2: what real feedback changed

Shipped after the original submission — grounded in a real changelog, not a claim.
🗄️
Supabase persistence
Render's free tier wiped sessions on idle. Now real Postgres — verified via a live restart test.
📆
Real calendar-based tracking
Day/week rollover checks the real date — not external sync, see Roadmap.
🎯
Task-level pacing questions
Classifies each task type, asks the right question — verified live.
🔍
Root-cause bug discipline
2 live 500-errors this work → 2 real fixes, root-caused not patched.
🧠
RAG for Nudge patterns
Curated reasoning patterns retrieved per-request (Supabase pgvector + Gemini embeddings) — not baked into every prompt as one fixed block.

What I learned

⚡
Action, not explanation
Life Happened became a single tap — no classifying.
⏱️
Time > tasks
Smart Spend beat task-management on engagement.
🧮
Trust = math, not words
Reserve Hours beat comforting language every time.
🤝
Build honestly
3 things stay simulated because the data doesn't exist yet.

Building DoneHo taught me that successful AI products aren't defined by the sophistication of their models, but by how effectively they solve real user problems.

Balancing user research, product strategy, system design, experimentation, and technical implementation — great product management is designing systems that stay valuable even when reality doesn't go as planned.
